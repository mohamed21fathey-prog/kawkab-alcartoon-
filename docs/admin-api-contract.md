# عقد واجهات لوحة الإدارة — كوكب الكرتون

> مواصفة تنفيذية فقط. هذه المسارات غير موجودة كخدمات عاملة بعد، ولا يجوز عرضها للمستخدمين كأنها متاحة.

## قواعد عامة
- كل المسارات تحت `/api/v1` وتعمل عبر HTTPS فقط.
- لا تعتمد أي صلاحية أو هوية أو قيمة رصيد مرسلة من المتصفح.
- جلسة آمنة عبر Cookie من نوع HttpOnly + Secure + SameSite، مع حماية CSRF للطلبات المغيّرة للحالة.
- كل عملية إدارية تتحقق من الدور `admin` على الخادم في كل طلب، وليس بمجرد إخفاء عناصر الواجهة.
- تحقق من المدخلات، وحدود معدل الطلبات، وأحجام الملفات، وأنواعها الفعلية.
- ردود الخطأ لا تكشف stack traces أو أسرارًا أو بيانات مستخدم آخر.
- كل عملية تغيير إدارية تسجل actor/action/target/outcome في `audit_logs`.
- جميع القوائم تستخدم pagination وحدودًا قصوى؛ لا تُرجع بيانات حساسة لا تحتاجها الشاشة.

## الجلسة والصلاحيات
| Method | Endpoint | الغرض |
|---|---|---|
| GET | `/auth/session` | معرفة حالة الجلسة الحالية |
| POST | `/auth/logout` | إنهاء الجلسة وإبطال الرمز |
| GET | `/admin/me` | تأكيد صلاحية الإدارة الحالية |

لا يُنشأ أول مدير عبر رابط تسجيل عام. تهيئة أول مدير تتم يدويًا وبإجراء آمن خارج واجهة المستخدم، ثم تُزال آلية التهيئة المؤقتة.

## لوحة المتابعة
| Method | Endpoint | الغرض |
|---|---|---|
| GET | `/admin/overview` | أعداد إجمالية مجمعة: المستخدمون والمشاريع والطلبات المعلقة |
| GET | `/admin/audit-logs` | سجل التدقيق مع فلاتر وصفحات |

تُعرض إحصاءات مجمعة فقط، ولا تُخترع أرقام تجريبية على أنها بيانات حقيقية.

## المستخدمون والمشاريع
| Method | Endpoint | الغرض |
|---|---|---|
| GET | `/admin/users?cursor=…` | قائمة مستخدمين ببيانات محدودة |
| GET | `/admin/users/{id}` | تفاصيل مستخدم مصرح بعرضها |
| PATCH | `/admin/users/{id}/status` | تعليق/إعادة تفعيل مع سبب وتسجيل تدقيق |
| GET | `/admin/projects?status=…` | قائمة المشاريع |
| GET | `/admin/projects/{id}` | تفاصيل مشروع مع التحقق من الصلاحيات |
| PATCH | `/admin/projects/{id}/review` | قبول/رفض/حجر مع سبب واضح |

لا يحق للمشرف الاطلاع على ملفات خاصة إلا عند وجود سبب تشغيلي وصلاحية موثقة، وتُسجل مشاهدة الملفات الحساسة.

## المدفوعات والرصيد
| Method | Endpoint | الغرض |
|---|---|---|
| GET | `/admin/payment-requests?status=pending` | قائمة طلبات التحويل للمراجعة |
| GET | `/admin/payment-requests/{id}` | تفاصيل الطلب وإثبات التحويل الخاص |
| POST | `/admin/payment-requests/{id}/approve` | اعتماد يدوي ذري |
| POST | `/admin/payment-requests/{id}/reject` | رفض مع سبب |
| GET | `/admin/users/{id}/wallet` | سجل الرصيد المحسوب من دفتر المعاملات |
| POST | `/admin/wallet-adjustments` | تعديل استثنائي موثق بسبب ومفتاح idempotency |

اعتماد طلب الدفع يجب أن يتم داخل معاملة قاعدة بيانات واحدة:
1. قفل/التحقق من أن الطلب ما زال `pending`.
2. التحقق من بيانات الإثبات ومطابقة المبلغ والمستلم يدويًا.
3. إنشاء معاملة شحن واحدة بحالة `approved` وبمفتاح idempotency فريد.
4. ربط الطلب بمعاملة الشحن وتغيير حالته إلى `approved`.
5. كتابة سجل تدقيق.
6. إذا فشلت أي خطوة، يتم rollback للجميع.

لا يُمنح الرصيد عند رفع صورة التحويل أو عند إرسال النموذج. الصورة ليست إثباتًا آليًا للدفع. لا توجد بوابة دفع مفعلة في هذه النسخة.

## المحتوى والإشراف
| Method | Endpoint | الغرض |
|---|---|---|
| GET | `/admin/moderation?status=pending` | قائمة العناصر المنتظرة |
| POST | `/admin/moderation/{id}/decision` | قبول/رفض/حجر مع reason code |
| GET | `/admin/content/sections` | الأقسام |
| POST | `/admin/content/topics` | إنشاء مسودة موضوع |
| PATCH | `/admin/content/topics/{id}` | تعديل مسودة |
| POST | `/admin/content/topics/{id}/publish` | نشر بعد مراجعة بشرية |

كل محتوى يبدأ غير منشور. الفحص الآلي لا يضمن اكتشاف كل المحتوى الضار، ويجب إبقاء الحالات عالية الخطورة للمراجعة البشرية.

## اختبارات قبول إلزامية قبل الإطلاق
- مستخدم عادي لا يستطيع استدعاء أي مسار إداري حتى لو أرسل الطلب يدويًا.
- لا يمكن الوصول إلى بيانات مستخدم آخر بتغيير ID في الرابط.
- انتهاء الجلسة وإبطالها يمنعان إعادة الاستخدام.
- تكرار اعتماد نفس طلب الدفع لا يضيف رصيدًا مرتين.
- فشل أي خطوة في اعتماد الدفع لا يترك رصيدًا أو حالة جزئية.
- لا يمكن اعتماد طلب دفع بلا معاملة شحن مطابقة للمستخدم.
- كل تغيير إداري ينتج سجل تدقيق.
- رفع الملفات الخاصة لا ينتج رابطًا عامًا دائمًا.
- اختبارات rate limiting وCSRF والتحقق من الملفات ومدخلات SQL/XSS.
- اختبارات النسخ الاحتياطي والاستعادة وحذف بيانات المستخدم وفق سياسة الخصوصية.

## بوابة التنفيذ
لا تُنشأ قاعدة D1 أو Worker أو Bucket ولا تُضاف Secrets حتى يوافق مالك المشروع صراحةً على المزود والخطة المجانية وشروط استخدامها. لا يُفعّل تسجيل الحسابات أو الدفع أو التوليد قبل اكتمال الاختبارات الأمنية والتشغيلية.
