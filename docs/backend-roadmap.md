# خطة البنية الخلفية — كوكب الكرتون

هذه وثيقة تخطيط فقط. لا تنشئ خدمات سحابية ولا حسابات ولا مفاتيح ولا موارد مدفوعة.

## قواعد لا يجوز تجاوزها
- لا تستخدم KIE.ai أو أي مزود توليد مدفوع بديل دون موافقة صريحة.
- لا تخزن أسرارًا أو مفاتيح API داخل ملفات الواجهة أو المستودع.
- لا تخصم رصيدًا من المتصفح؛ كل عمليات الرصيد يجب أن تتم على الخادم داخل معاملات موثوقة.
- لا تعتبر إتمام الدفع ناجحًا اعتمادًا على عودة المتصفح؛ يجب التحقق من إشعار بوابة الدفع على الخادم.
- لا تنشر ولا تدمج إلى main قبل مراجعة المستخدم وموافقته.
- لا تعرض وظائف غير منفذة على أنها تعمل.

## البنية المقترحة للمراجعة
الخيار المرشح للدراسة: Cloudflare Workers + D1 + R2، مع الالتزام بالخطة المجانية وحدودها الحالية فقط. هذا ترشيح مبدئي وليس اعتمادًا أو إعدادًا فعليًا. يجب التحقق من الأسعار والحدود قبل أي إنشاء موارد.

### المكونات
1. واجهة ثابتة: تبقى منفصلة عن الأسرار، وتستدعي واجهات الخادم عبر HTTPS.
2. Worker API: مصادقة الجلسات، التحقق من الصلاحيات، إدارة المشاريع، الرصيد، الطلبات، وسجل العمليات.
3. D1: بيانات المستخدمين والمشاريع والطلبات والمعاملات وسجل الرصيد.
4. R2: ملفات المستخدمين والمخرجات، مع روابط تنزيل مؤقتة وصلاحيات مناسبة.
5. لوحة إدارة محمية: إدارة المستخدمين والطلبات والمنتجات ومراجعة سجل الرصيد.

## نموذج بيانات أولي
- users: id, email, password_hash أو معرف موفر مصادقة موثوق، role, created_at
- projects: id, user_id, title, status, created_at, updated_at
- assets: id, project_id, owner_id, object_key, media_type, size_bytes, created_at
- wallets: user_id, balance
- wallet_ledger: id, user_id, delta, reason, reference_id, created_at
- orders: id, user_id, package_id, amount, currency, status, provider_reference, created_at
- products: id, title, description, price, object_key, is_active
- audit_log: id, actor_id, action, target_type, target_id, created_at

## ضوابط الأمان والرصيد
- لا تحفظ كلمات المرور كنص صريح.
- تحقق من ملكية المشروع والملف في كل طلب، وليس في الواجهة فقط.
- استخدم صلاحيات أقل امتيازًا، وحدودًا للطلبات، والتحقق من المدخلات.
- اجعل سجل الرصيد append-only، ولا تسمح بتعديل الرصيد من المتصفح.
- اربط كل شحن بمعاملة دفع فريدة، مع منع تكرار معالجة إشعارات الدفع.
- لا تسلم منتجًا رقميًا إلا بعد التحقق من الدفع على الخادم.
- لا تضع أسرارًا في GitHub أو JavaScript المرسل للمتصفح.

## مراحل التنفيذ المقترحة
1. مراجعة مزود الاستضافة المجاني وحدوده وسياسة الاحتفاظ بالبيانات.
2. اعتماد المستخدم للمزود قبل إنشاء أي موارد أو ربط حساب.
3. إعداد بيئة اختبار منفصلة عن الموقع المنشور.
4. بناء المصادقة والصلاحيات ثم اختبارها.
5. بناء المشاريع والملفات والتخزين.
6. بناء سجل الرصيد والطلبات دون تفعيل دفع حقيقي.
7. اختيار بوابة دفع مصرية بموافقة المستخدم، ثم تنفيذ التحقق الخادمي واختبارات sandbox.
8. دراسة إنتاج الفيديو كمرحلة مستقلة؛ لا يوجد توليد فيديو مجاني مضمون أو غير محدود بمجرد إعداد قاعدة البيانات.

## ما لم يتم تنفيذه
لا يوجد في هذه المرحلة Worker أو قاعدة بيانات أو تخزين سحابي أو تسجيل حسابات أو دفع أو توليد فيديو. هذه الوثيقة لا تنشئ أيًا منها.
